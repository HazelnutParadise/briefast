## Context

每日報告於台股開盤前產出，API 將整份 JSON 存入 SQLite，首頁與歷史頁從同一份資料渲染。現有資料無大盤預測欄位。法說會會前報告獨立儲存，只有與報告當日有關且資訊已取得的內容可作為判斷依據。

## Goals / Non-Goals

**Goals:** 清楚呈現報告日台股加權指數的方向判斷與理由；新報告流程涵蓋新聞、籌碼和相關法說資訊；舊資料與既有 API 客戶端繼續運作。

**Non-Goals:** 即時盤中預測、精確點位或機率、歷史預測績效、從個股預測機械加總成指數預測、修改法說會蒐集或發佈規則。

## Decisions

### Add optional market_outlook to the report JSON

新增 `market_outlook: {"direction": "up|down|range|uncertain", "summary_md": "..."}`。`up` 與 `down` 指報告當日加權指數收盤相對上一交易日收盤偏高或偏低；`range` 指預期震盪、沒有明顯單向優勢；`uncertain` 指資料不足或訊號衝突，無法做可靠的方向判斷。欄位選填以保留既有報告與客戶端；有提供時方向與理由都必須有效。沿用全量 JSON 儲存，不新增資料表或 migration。

### Synthesize the forecast from report evidence

每日流程在完成新聞、籌碼、個股與法說整理後，衡量對大盤有影響的因素，辨明資料日期、影響範圍和相反訊號。理由只引用本次已查證並寫入報告或相關法說 brief 的資訊；缺某類資訊要明示，不能補造。籌碼是前一交易日資料，不當成當日結果或單獨的因果證據。沒有足夠證據時使用 `uncertain`，不硬給漲跌。這比依看漲與看跌個股數量投票更符合加權指數的實際構成。

### Render forecast within the existing overview

在首頁與歷史頁的「盤前總覽」中，以明確的「今日大盤走勢預測」標示方向及理由；沿用台股紅漲綠跌與原有無圓角、無陰影版面。缺欄位的舊報告不顯示預測，也不改五個固定區塊順序。

## Implementation Contract

- 有 `market_outlook` 的報告 API 請求接受上述四個方向與非空白 `summary_md`；方向錯誤或理由空白時回 HTTP 400、列明 `market_outlook` 錯誤，且不存報告。成功後按日期讀取保有相同欄位內容。缺欄位的舊 payload 仍成功。
- 首頁與歷史報告顯示 `今日大盤走勢預測`、中文方向與經既有 Markdown 渲染的理由。上漲使用紅色、下跌使用綠色、中性方向使用中性色；舊資料沒有預測時不渲染空白標籤。
- 每日 skill 的 JSON 範例包含完整預測物件，並要求在蒐集完成後根據當日相關新聞、上一交易日籌碼、影響指數較大的個股與相關法說內容做總體判斷。資料不足或衝突時能選 `uncertain`，不能編造點位、機率或缺少來源的事實。
- 驗收：報告欄位驗證與 API roundtrip 測試、首頁與歷史頁渲染測試、舊報告相容測試、`go test ./...`、`spectra validate`，以及實際查看桌面與窄版畫面。

## Risks / Trade-offs

- [每日預測被誤認成保證] → 標示為「預測」並保留報告頁既有免責聲明；理由要說明相反訊號與不確定性。
- [只有部分資料可用] → 使用 `uncertain`，在理由指出缺口，不憑空補值。
- [舊客戶端同日重送全量報告後覆寫預測] → 維持既有全量覆寫語意，正式每日流程更新後每次都產生預測；不在 API 默默合併舊欄位。

## Migration Plan

先部署支援新欄位的網站，再以更新後的每日流程發送新格式。回退網站程式時需停用新版每日流程，避免舊 API 拒絕新欄位；既有儲存 JSON 無須搬移。
