## Context

daily-brief 是給 Cowork agent 執行的操作手冊，不是程式。它先前假設執行環境會注入環境變數、來源表沿用專案初期未逐一驗證的入口，判讀也只分產業與個股兩種視角敘述、沒有重要程度概念。2026-08-09 對所有來源做了實際連線與全文抓取驗證，並對擬新增的撰寫訣竅跑過一輪辯論檢驗，本文件記錄由此形成的判斷。本次不動 Go 程式、報告 schema 與網站版面。

## Goals / Non-Goals

**Goals:**

- 設定介面改成執行工作區實際拿得到的形式。
- 來源表每一條都指向實測可達、且能取得全文的端點。
- 判讀有明確的重要程度依據與可執行的撰寫訣竅，且不因此引入幻覺風險。

**Non-Goals:**

- 不動 Go 程式、報告 schema、網站版面與 API 行為。
- 不把 .env 讀取做成程式碼或共用腳本，它是手冊的操作指示。
- 不新增排序分數欄位到報告 JSON。
- 不擴充來源到已驗證清單以外，也不恢復 UDN。
- 不改變主次來源分流，鉅亨網仍是唯一主來源。

## Decisions

### 執行工作區根目錄的 .env

skill 是可攜的操作手冊，會被複製到不同工作區；把秘密綁在手冊目錄等於讓金鑰跟著手冊走。改為讀執行工作區根目錄的 .env，手冊只描述相對位置不寫死絕對路徑，skill 目錄僅放不含真值的 .env.example。捨棄環境變數方案的理由是 Cowork 執行環境沒有注入環境變數的介面，agent 實際拿不到值。

### 新聞來源表

改為列出具名端點而非「某某網站」，理由是入口首頁是編輯檯排版，agent 自行找新聞會漏掉窗口內的中小新聞，且各站的清單頁擋抓程度不一。實測結果決定了四項調整：UDN 所有公開 RSS 的 item 標題與連結皆為空，無法使用，改由自由時報財經 RSS 補位；CTEE 分類頁 HTML 回 403 但 rss_web 端點可直接取得，因此移除無頭瀏覽器需求；cnyes 列表 API 的回應已含完整內文與股票標注，取消詳情頁抓取；TWSE 對高頻請求會鎖 IP，因此新增節流。

### 證交所節流規則

TWSE 每次只拉兩個資料集，請求量極小，複雜的指數退避沒有收益。採「序列、間隔至少 5 秒；遇阻等 60 秒重試一次；再失敗即當次要來源失敗」的固定規則，與既有來源成敗把關的主次分流直接銜接，不引入第二套失敗處理邏輯。

### 排序只影響事件領銜、詳略與先後

排序解決的是「摘要詳略無依據」，不是「報告太長」。若允許用排序篩選，會與既有「不設數量上限、能判斷的都列」直接衝突，也會讓當日新聞稀少時的報告被進一步削薄。因此兩輪都明文限制排序的作用範圍，並在個股輪補述同一則新聞可在兩輪有不同名次，以說明分兩輪的用意。

### 「來源綁定」與「省略式出口」兩道護欄

撰寫訣竅本質上是在要求模型輸出更多資訊，而模型補足資訊最省力的方式就是從訓練記憶取值，這與既有的基本面引用紀律直接衝突。因此每條訣竅都加上「資訊只能來自本次新聞或本次抓取」的來源綁定，缺料時一律整句省略而非改寫成佔位句——佔位句本身又會違反既有的禁範本化空話規則。唯一例外是供需歸因：在歸因處保持沉默會被讀成隱含確定，因此改為明寫「驅動未明」。辯論過程中因此刪去「對比基準用季節性歷史數字」與「量級算不出時寫無法估算」兩項原始構想，並把「週期或結構」由獨立訣竅降為排序依據持續性項的寫法附註。

## Implementation Contract

- **設定行為**：agent 從執行工作區根目錄的 .env 以 KEY=VALUE 讀取 BRIEFAST_URL 與 BRIEFAST_API_KEY；檔案不存在或任一鍵缺漏、空白時，在蒐集開始前停止並回報缺少哪一項，不蒐集、不組稿、不 POST。skill 目錄的 .env.example 只含兩個鍵名與佔位值，且不得被 gitignore 排除。
- **蒐集行為**：所有清單取得都指向 SKILL.md 列出的具名端點；cnyes 內容取自列表回應不另抓詳情頁；CTEE 以 RSS 取得文章網址後用一般 HTTP 抓內文；TWSE 請求序列化且間隔至少 5 秒，遇阻等 60 秒重試一次後即歸入次要來源失敗處理。
- **判讀行為**：判讀分產業輪與個股輪依序執行，每輪動筆前依該輪五項依據排序；排序結果只反映在事件領銜、著墨深度與先後，收錄與否不受排序影響。
- **撰寫行為**：兩輪的訣竅皆受來源綁定與省略式出口約束；缺料處除產業供需歸因寫「驅動未明」外，一律整句省略，不留佔位句。
- **驗收標準**：以內容審查驗證——SKILL.md 全文不再以環境變數作為設定介面、無 UDN 與無頭瀏覽器需求、每個來源有具體端點、兩輪各有完整五項依據與「排序不影響收錄」明文、兩道護欄在兩輪皆出現且「明寫缺料」僅出現於供需歸因一條；並以 git check-ignore 確認 .env 被忽略而 .env.example 未被忽略；spectra validate 通過。
- **範圍邊界**：in scope 為 skills/daily-brief/SKILL.md、skills/daily-brief/.env.example 與 daily-brief-skill spec；out of scope 為 Go 程式、報告 schema、網站版面、API 行為與 seen.py。

## Risks / Trade-offs

- [來源端點寫死在手冊，站方改版時會整條失效] → 端點失效會由來源成敗把關當場攔下：主來源失效即停止發布，次要來源失效照發並揭露，不會靜默產出殘缺報告。
- [撰寫訣竅要求更多資訊，可能誘發模型以記憶補值] → 每條訣竅綁定來源、缺料整句省略，並在送出前檢查清單加入一條「所有數字、預期與歸因都能回指本次來源」的檢核。
- [反例正例對照表可能被當成可複製的範本句] → 兩張表都標明為示意寫法而非範本句，並在訣竅本文要求標題與首句不得互相複述。
