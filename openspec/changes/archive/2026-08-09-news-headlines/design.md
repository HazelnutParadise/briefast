## Context

Briefast 的報告版面寫死在 Go 程式，agent 只提供內容；報告以完整 JSON 存於 SQLite 的 reports 資料表，`internal/report` 負責驗證、`internal/site` 負責渲染。目前產業分類是單一 `summary_md` 大段文字，內部靠粗體短語分段；個股條目沒有標題欄位。本 change 把兩處的一句話標題升為結構化欄位，讓驗證與版面都能掌握標題。網站尚未上線、資料庫沒有已發布報告，因此可直接換格式。

## Goals / Non-Goals

**Goals:**

- 產業分類底下的每個事件都有可驗證的一句話標題與獨立內文。
- 每檔個股都有可驗證的一句話標題，呈現在條目識別區。
- 版面能對標題做與內文不同的排版處理。

**Non-Goals:**

- 不保留舊的 `industries[].summary_md` 單欄格式，也不寫雙格式相容邏輯。
- 不改資料庫結構、不新增 migration。
- 不改報告的五區塊版面順序與固定分類名稱。
- 不把 `watch_md` 下放到事件層級，觀察重點維持在產業分類與個股條目層級。
- 不加入標題字數上限的程式檢查，長度由 skill 規範。

## Decisions

### 產業改為事件陣列而非 Markdown 慣例

一個產業分類底下有多個事件，數量每天不同，無法用單一欄位承載標題。若維持單一 `summary_md` 並約定「每段以粗體標題開頭」，API 無從驗證每段是否真的有標題，版面也只能把標題當成行內粗體，做不出獨立小標。改為 `events[]` 後，缺標題會在 ingest 當下被擋下，版面也能逐一渲染事件。代價是報告格式變動，但尚未上線，沒有實際成本。

### 個股標題採欄位而非寫進 summary_md

個股條目一則一個標題，天然對應單一欄位。版面的個股條目分成左側識別欄（名稱、代號、多空標籤）與右側內文欄，標題屬於識別資訊，放進左欄才符合既有版面邏輯；若寫在 `summary_md` 開頭則只能留在右欄內文流裡，與券商晨報「名稱 — 標題」的閱讀習慣不符。

### 驗證嚴格度與錯誤訊息形狀

沿用既有逐項累積錯誤的作法：每個違規都帶索引寫進 `errors` 陣列（例如指出第幾個產業的第幾個事件缺標題），一次回報所有問題而非遇到第一個就中止，讓 agent 能一次修完重送。空 `events` 視為違規而非空陣列容忍，因為固定四分類的規則已允許「該分類當天無新聞就整個省略」，留下一個沒有事件的分類只會是漏填。

## Implementation Contract

- **資料形狀**：`internal/report` 的 Industry 型別移除 `SummaryMD`，改為事件切片，JSON 名稱 `events`；新增事件型別，含 `headline` 與 `summary_md` 兩個字串欄位。StockNews 型別新增字串欄位，JSON 名稱 `headline`。
- **驗證行為**：`industries` 條目的 `events` 為空、任一事件的 `headline` 或 `summary_md` 空白、任一 `stock_news` 條目的 `headline` 空白，皆使 `POST /api/report` 回 400，`errors` 逐項列出並標明是第幾個產業、第幾個事件，整份報告不落庫，update_log 記 rejected-schema。
- **渲染行為**：產業分類內逐一渲染事件，事件標題為獨立於內文的小標題區塊，內文接在其下；同一分類多個事件之間可辨識為不同段落。個股條目的標題渲染在左側識別欄，位於股票名稱與多空標籤之間。
- **驗收標準**：`go test ./...` 全綠。internal/report 測試涵蓋空 events、事件缺 headline、事件缺 summary_md、個股缺 headline、正常五種案例；internal/site 測試斷言產業事件標題與內文都出現在產業區塊、個股標題出現在識別欄；internal/api 測試涵蓋缺標題的 payload 回 400 且不落庫。
- **範圍邊界**：in scope——報告型別、驗證、版面渲染、樣式與 SKILL.md 內容；out of scope——資料庫 schema、admin 後台、唯讀端點行為、舊格式相容。

## Risks / Trade-offs

- [報告格式變動後，SKILL.md 若未同步，agent 送出的舊格式 payload 會被 400 擋下，晨報發布失敗] → 同一 change 內同步改 SKILL.md 與 JSON 範例，並在送出前檢查清單加入事件與標題檢核，兩者一起部署。
- [執行模型為滿足必填而寫出與內文重複或空泛的標題] → SKILL.md 明文要求標題寫出發生什麼事與影響，禁止短語標籤與複述內文首句。
- [事件拆分過細導致每個分類條目數暴增、版面擁擠] → SKILL.md 規範同一分類的事件依主題合併，一個事件涵蓋一組相關動態，而非一則新聞一個事件。
