## Context

盤前報告目前用 `market_outlook.direction` 預測收盤方向，用 `summary_md` 解釋依據。每日流程在 9:00 前產生報告，無法取得當日實際盤中走法；因此預測應是可檢驗的情境敘述，不能寫成已發生的盤中事實。

## Goals / Non-Goals

**Goals:** 讓讀者一眼看懂可能的開盤、盤中、尾盤演變，以及哪項訊號會使原判斷失效；維持舊報告可讀。

**Non-Goals:** 分鐘級曲線、精確轉折時間、指數點位／機率、盤中即時更新、以假資料補足路徑。

## Decisions

### Add an optional trajectory_md field

在既有 `market_outlook` 內加入選填 `trajectory_md`。新每日報告必須填寫，API 接受舊版無此欄位的物件以保留相容；若欄位明確出現卻只有空白，回 400。使用單一 Markdown 欄位可敘述基準路徑與條件，不把不確定市場硬塞進固定型態或指定轉折時間。

### Write a baseline path with conditional pivots

每日流程先判斷開盤傾向，再描述盤中是延續、震盪或回吐，以及尾盤的基準情境，並指出可觀察的條件何時會改變它。這些都是盤前推論而非盤中資料；未取得即時價格、成交量或市場廣度時只能寫成「若…則…」。證據不足以支持分段走勢時，`trajectory_md` 明示「盤中路徑無法可靠判斷」，並寫出最關鍵的觀察條件。

### Promote trajectory in the overview

在大盤預測區塊以「預期走法」顯示 `trajectory_md`，排在方向標籤和判斷依據之間。沿用現有無卡片、無細規線的文字層級，舊報告無路徑時仍呈現既有方向及理由，不加佔位文字。

## Implementation Contract

- `market_outlook.trajectory_md` 為選填 Markdown 文字；若 JSON 提供非空值卻不是字串或只有空白文字，API 回 400 並指出欄位，且不寫入報告。有效路徑在按日期 GET 時原樣讀回。未提供時既有 `market_outlook` 與完全沒有 `market_outlook` 的報告均可讀。
- 有路徑時首頁與歷史頁在「今日大盤走勢預測」下顯示「預期走法」及渲染後的內容，且排在方向依據前；舊報告無路徑時不顯示空白標籤。原有五個固定區塊及紅漲綠跌不變。
- 每日 skill 的 JSON 範例與檢查點要求 `trajectory_md`：開盤、盤中、尾盤的基準路徑及至少一個可使走法改變的條件；若證據不足則明示無法可靠判斷，不捏造具體轉折、點位、機率或盤中已發生的事。
- 驗收：schema 與 API 的有效／空白／舊資料測試、首頁與歷史頁渲染及舊資料測試、每日範例驗證、`go test ./...`、Spectra 驗證及實際桌面與窄版畫面檢查。

## Risks / Trade-offs

- [文字暗示精確預測能力] → 標示「預期走法」，要求條件句與相反訊號，不提供假精確的分鐘級曲線。
- [舊報告只有方向] → 繼續顯示既有內容，新版每日流程才逐日產生路徑。
- [長文字擠壓手機版] → 保持單欄自然換行與既有字級，不新增水平圖表。
