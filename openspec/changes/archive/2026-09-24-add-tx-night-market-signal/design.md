## Context

網站已有 `market_outlook` 的文字與定性三點圖，盤前總覽仍在同一主欄。每日晨報 skill 已取得最近已收盤的那斯達克與費半資料，卻未讀取臺指期夜盤。2025-01 至 2026-09 的單訊號回測顯示夜盤對開盤方向較有用，對開盤後至收盤的方向則較弱。資料來自期交所的 CSV，盤後列的「交易日期」是次一一般交易日歸屬日，必須避免與同日一般時段收盤比較造成偷看未來。

## Goals / Non-Goals

**Goals:**

- 在報告產生前以期交所原始資料形成可核對的 TX 夜盤方向，並納入開盤情境。
- 使跨週末、跨月及換月時仍以實際前一交易日、同一契約和正確時段配對。
- 資料失敗時讓既有晨報照常完成，將缺漏留在操作者回報。

**Non-Goals:**

- 不變更網站版面、盤前總覽、報告 JSON 或既有歷史報告。
- 不把單一夜盤訊號轉成收盤保證、點位、漲跌幅或三階段圖。
- 不引入自動交易、正式預測模型或新的付費行情來源。

## Decisions

### 用期交所 CSV 與純標準函式庫擷取夜盤方向

每日流程以期交所 `futDataDown` 取得報告日和前一交易日的 TX CSV，保留原檔於工作資料夾。新增純標準函式庫的命令列解析器，明確檢查 CP950、欄名、日期、契約、交易時段、收盤價與成交量。這比請 agent 從長表手動選列更能避免換月或時段誤配；無需新套件或正式網站 API。上一交易日由既有已驗證的台股交易日取得，不能直接將報告日減一天。

### 用同契約前一日盤收比較且只影響開盤情境

報告日 `盤後` 中選成交量最高的單月 TX 契約，與前一交易日 `一般` 的相同契約收盤比較。方向以差額正負決定，零差額回報 `flat` 而不判多空。夜盤可在 `trajectory_md` 的開盤段落作佐證；`direction` 仍指當日大盤收盤相對前收，盤中和尾盤需各有其他證據。與費半、那斯達克或台股消息背離時，`summary_md` 說明背離及取捨。

### 失敗時回退既有市場判讀

官方 CSV 沒有完成的盤後列、日期錯置、合約或價量有歧義、請求失敗時，重試一次後把 TX 視為缺漏，繼續使用既有已驗證資料。缺漏原因只寫入執行回報，不寫進公開報告。不能因夜盤缺漏而虛構方向或畫圖。

## Implementation Contract

- 解析器介面：`python3 skills/daily-brief/scripts/tx_night.py --report-date YYYY-MM-DD --previous-date YYYY-MM-DD --report-csv PATH --previous-csv PATH`。成功只在 stdout 輸出一行 JSON，包含 `report_date`、`previous_regular_date`、`contract`、`night_close`、`previous_regular_close`、`change_points`、`change_pct`、`direction`、`night_volume`；`direction` 為 `up`、`down` 或 `flat`。失敗以非零狀態及 stderr 說明原因，stdout 不輸出部分結果。
- 選列規則：只接受 `契約=TX`、單月六位到期月份、報告日 `盤後` 且成交量大於零的列；最大成交量須唯一；在前一交易日 `一般` 中找到唯一同契約列。收盤價須為正且為有限數。來源列的交易日期必須精確等於兩個參數。不能用報告日 `一般` 列或另一到期月份替代。
- 每日流程：在撰寫 `market_outlook` 前取得並驗證兩份官方 CSV。若解析成功，記錄資料日期、契約、兩價與方向；用於開盤傾向並與其他訊號比對。夜盤資料無法用時重試一次，然後略過夜盤，照常組稿與發布。
- 驗收：離線測試涵蓋正常、跨週末、換月、零變動、缺列、重複最高量、錯日期和格式錯誤；執行解析器可重現 2026-09-24 相對 2026-09-23 的 TX 202610 差額 -427；日報 skill 與規格要求夜盤只作開盤佐證，且不改動盤前總覽和既有輸出欄位。

## Risks / Trade-offs

- [官方 CSV 盤前尚未上架] → 檢查歸屬交易日與盤後列，重試後略過，不拿舊日資料充當昨夜。
- [單訊號與美股或台股消息背離] → 同列對照並說明取捨，避免把開盤訊號當作全天走勢。
- [日期或換月配錯造成假命中] → 強制同契約、前一交易日與交易時段配對，離線測試涵蓋跨週末及換月。
