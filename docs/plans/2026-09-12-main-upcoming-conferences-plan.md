# Plan: 近期法說會區塊與會前預測報告
_Created: 2026-09-12 - plan-grilling - briefast:main_

狀態：決策已鎖定，進入 `/spectra-propose`。

## Problem

讀者開盤前掃報告時，看不到「哪幾家公司這幾天要開法說會」，也沒有一份在法說會前就寫好的多空判斷。現有報告只在個股 `watch_md` 裡零星提到「追蹤下一次法說」，沒有集中列表，也沒有針對法說會本身的預測。

## 資料來源查證（2026-09-12 實測）

- **證交所 OpenAPI 沒有「未來法說會排程」資料集。** 掃過 `openapi.twse.com.tw/v1/swagger.json` 與櫃買 `tpex.org.tw/openapi/swagger.json`，含「法說」「說明會」「Investor」「Conference」的只有 ESG 年度法說會次數統計（`t187ap46_L_7`／`t187ap46_O_7`），無排程。
- **公開資訊觀測站「法人說明會一覽表」不能程式化取得。** 舊版 `ajax_t100sb02_1` 回 800 bytes 空頁，新版 `mops/api/t100sb02_1` 各種參數一律 302。
- **可用來源：重大訊息「第 12 款」。** 每日流程已抓的 `t187ap04_L`（上市）與 `mopsfin_t187ap04_O`（上櫃）裡，`符合條款` 為「第 12 款」的就是法說會公告，`說明` 欄有固定格式：`1.召開法人說明會之日期：115/09/15`、`2.時間`、`3.地點`、`4.擇要訊息`。2026-09-11 那天上市 92 則中有 17 則、上櫃 46 則中有 2 則。
- **公告通常只提前 1 到 5 天。** 因為只有當日快照，排程必須由每日流程逐日累積，不能單次抓齊。
- **多數第 12 款是「受邀參加券商論壇」，不是自辦財報法說。** 17 則中只有 4 則是自辦（新紡、南帝、中石化、英業達的複合公告），且「自辦／受邀」要從主旨與擇要訊息判斷，沒有獨立欄位。

## Reframe

使用者說的是「一塊區域列近期法說會」，實際在描述的是三件事：

1. **一份會跨天累積的排程資料**，和現有「同日全量覆寫」的報告模型不同，需要新的存放方式。
2. **一種新的判讀對象**：現有 call 是「今天的新聞看多看空」，會前預測是「法說會後股價相對會前的方向」，判斷依據（基本面、法人預期、近期消息）與驗證時點都不同。
3. **一個可事後對答案的承諾**。會前預測寫了方向，法說會後就能驗證。這是這個功能和其他區塊最大的差別，也是最容易失去公信力的地方。

可能錯的假設：

- 「近期要開法說會的公司」在讀者心中是台積電、聯發科這種自辦季度法說；但資料裡八成是受邀券商論壇，若全部列出，卡片會被中小型股淹沒，預測也沒有材料可寫。
- 每日流程目前只判讀「時間窗口內有新聞」的股票；法說會前的公司未必當天有新聞，要寫預測報告就得為它額外蒐集基本面（月營收、上季財報、昨收價、籌碼），這是新的蒐集工作，不是現有流程的副產品。

另一種框法：不做「預測」，做「法說會前重點整理」（市場關注什麼、上次法說說了什麼、這次要看什麼）。免責壓力小很多，但和使用者要的「看漲或看跌」不同。此方案不推薦，因為使用者明確要方向。

## Scope decisions

### Chosen scope

- 讀者可以在首頁看到一個「近期法說會」區塊，列出未來 N 個交易日內要開法說會的公司卡片，每張卡片有公司名、代號、法說會日期、自辦或受邀、以及會前預測方向（會後看漲／會後看跌／無法判斷）。
- 讀者可以點進單一公司卡片，看到該場法說會的會前預測報告：預測方向、依據（本次抓到的基本面數字、近期消息、籌碼）、法說會要看的重點、來源連結、資料日期。
- 每日流程可以把當天新公告的法說會登記進排程，並為符合條件的場次產出會前報告，透過現有 Bearer 驗證的 API 送進站台。
- 法說會日期過了之後，卡片自動從「近期」區塊消失，報告仍可從連結進入（不刪）。
- 讀者可以在法說會區塊看到目前的預測準確度，格式為「近 N 場命中 X 場」，以會後第 1 個交易日收盤價相對會前一日收盤價的方向對照預測方向計算，「無法判斷」不計入分母。
- 每日流程可以在法說會後回填結算結果（會前收盤、會後收盤、命中與否）。

### Explicitly out

- 券商論壇型「受邀」場次。不列卡片也不寫報告（決策 5A）。
- 法說會逐字稿、簡報檔抓取與摘要。MOPS 不可程式化取得。
- 後台管理排程（手動增刪）。先讓每日流程自動維護。

### Deferred

- 首頁以外的入口（歷史頁列出過去的法說會報告）。

## Assumptions to validate

- 第 12 款公告能穩定地把「自辦」和「受邀」分出來。風險：分錯會讓重要法說漏列，或被論壇淹沒。驗證方式：先拿一到兩週的公告人工標記，寫成 skill 裡的判斷規則。
- 每日流程有足夠材料為會前公司寫預測。風險：沒有當期新聞時只剩月營收與籌碼，模型可能硬寫方向。對策：允許「無法判斷」，並要求依據不足就標 none。
- 預測窗口取「未來 5 個交易日」夠用。風險：公告提前天數短，太長的窗口大多是空的。

## Success metric

上線兩週內，每個交易日首頁至少列出當週的自辦法說會，且每張有預測方向的卡片點進去都有寫明資料日期與來源的報告，沒有一張是空報告或佔位內容。

## Failure modes

- 排程資料模型和「同日全量覆寫」衝突，導致每天 POST 把前幾天登記的場次蓋掉。對策：法說會排程用獨立資料表與獨立 endpoint，以「代號＋法說會日期」為 key 做 upsert，不放在 report payload 裡。
- 預測方向與現有 `calls` 的多空互相打架（同一檔今天短線看空，法說會前又寫會後看漲）。對策：報告裡要求說明兩者時間尺度不同；站台不做自動一致性檢查。
- 免責聲明覆蓋不到新頁面。對策：法說會報告頁沿用固定 footer，spec 裡明列。
